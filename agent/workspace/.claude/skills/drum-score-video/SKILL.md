# 연주 영상 → 악보 + 송 맵

드럼 커버 채널들은 연주 화면 위나 아래에 **악보 띠**(보통 한 줄 4마디)를 깔고, 연주에 맞춰 띠를 통째로 넘긴다.
그 띠들을 순서대로 모으면 곡 전체 악보가 되고(반복 기호 없이 연주 순서 그대로), 띠가 넘어가는 시각은
그 마디가 시작하는 시각과 거의 같다. 이 둘로 악보와 송 맵을 만든다.

예시 곡과 정답은 [examples.md](examples.md) — 판단이 애매하면 읽는다.

## 순서

1. **get_job** — 곡 길이·검출 BPM·이미 악보가 있는지(has_score, overwrite_score)를 본다.
   has_score 인데 overwrite_score 가 false 면 끝까지 만들되 저장은 거절된다 — 처음부터 알고 간다.

2. **download_video** — 축소 장면들로 화면 구성을 파악한다.
   - 악보 띠가 **위**인지 **아래**인지, 띠가 언제부터 나오는지(인트로에 띠가 없는 영상도 있다)
   - 템포 표기: 첫 띠의 `♩ = 138`, 또는 화면 구석의 `Tempo = 150`
   - 방해물: 띠 위를 지나가는 **진행 커서**(파란 칸), 띠 오른쪽 위의 **"Next" 미리보기**,
     띠 안의 **가사 줄**, 띠 위의 **자막**, 발 카메라 창

3. **find_score_band** — 후보 상자를 확인한다. 상자가 악보 띠를 다 덮는지(구간 이름 상자·마디 번호·
   아래 음표까지), "Next" 미리보기 같은 **다른 악보가 들어가지 않는지** 본다. 틀리면 **look** 으로
   좌표를 재서 직접 정한다 (x0 는 0, x1 은 영상 폭이면 된다; 미리보기 창이 띠와 겹치면 x 를 줄인다).

4. **extract_strips(box, bpm)** — bpm 은 악보 템포(모르면 get_job 의 검출 BPM).
   결과 표의 ⚠ 는 "띠가 화면에 있던 시간으로 보면 마디 수가 다르다"는 뜻이다. 원인은 셋 중 하나다:
   - **마디선을 못 찾음/잘못 찾음** → show_strips 로 보고 edit_strip(add_bar/remove_bar).
     빨간 선이 음표 기둥에 붙어 있으면 잘못 찾은 것, 마디선인데 빨간 선이 없으면 놓친 것.
     첫 띠의 박자표·음자리표는 마디가 아니다.
   - **같은 띠가 연달아 두 번** (반복 구간을 같은 그림으로 두 번 보여줌 → 화면이 안 바뀌어 하나로 합쳐짐)
     → 시간이 정확히 2배면 edit_strip(repeat=2). 구간 이름 상자만 다른 경우는 따로 잡힌다.
   - **마지막 띠** — 곡이 끝나고도 띠가 남아 있으면 시간이 길다. 무시해도 된다.
   - **띠 하나가 통째로 빠짐** → 앞 띠의 끝과 다음 띠의 시작 사이가 비거나, align_audio 의 strip_lead_sec 가
     어느 띠부터 한 띠 길이만큼 벌어진다. look 으로 그 시각을 보고 add_strip(t, t1) 로 끼워 넣는다
     (다른 띠를 repeat 로 늘려 마디 수만 맞추지 말 것 — 악보 그림이 틀린다).
   악보가 아닌 장면(제목 화면·엔딩)이 띠로 잡히면 edit_strip(skip=true).
   **모든 띠를 show_strips 로 한 번씩은 본다** (6~8개씩). 마디 번호가 띠 왼쪽에 적혀 있으면
   (예: `21`) 빨간 숫자와 맞는지 대조한다 — 가장 확실한 검산이다.

5. **구간 이름** — 띠 안의 네모 상자 글자(`Aメロ`, `Chorus`, `Intro1` …)를 읽어
   edit_strip(marks=[{measure: 띠 안 마디 번호(0부터), text}]) 로 넣는다. 상자가 없는 영상이면
   비워 둔다(이름 없이 저장해도 된다). 자막·가사·`HH open` 같은 연주 지시는 구간 이름이 아니다.

6. **박자 예외** — 모든 마디가 4/4 가 아니다. 이런 마디를 찾아 {마디번호: 박수} 로 기록해 둔다:
   - **못갖춘마디**: 첫 마디가 2박뿐(스네어 필인만, 또는 2박 쉼표) → {1: 2}
   - 중간의 2/4·3/4 마디, 박자표가 바뀌는 곳 (띠에 `3/4` 같은 숫자가 보인다)
   마디 폭이 다른 마디의 절반쯤이면 의심한다.

7. **align_audio(bpm, beats)** — 결과를 읽는 법:
   - `offset.z` ≥ 8 이고 `ratio` ≥ 1.15 면 영상 소리와 곡이 잘 맞은 것. 낮으면(라이브·편곡 다름) anchor 를 의심한다.
   - `grid.bpm` 은 곡 드럼에서 잰 템포. 악보 템포와 0.5 넘게 다르면 grid.bpm 을 쓴다(곡 쪽이 진실).
   - `anchor.anchor` = 1마디 1박. `strip_lead_sec` 가 0 근처에 고르게(±0.3초) 모이면 맞다.
     한쪽으로 한 마디 길이만큼 벌어지는 띠가 있으면 그 앞의 마디 수가 틀렸다 → 4로 돌아간다.
   - 첫 마디가 못갖춘마디면 beats 에 넣고 다시 돌린다 (anchor 가 그만큼 당겨진다).

8. **build_score(tempo)** — 앱의 악보 분석기로 다시 읽은 마디 수가 띠 마디 수와 같아야 한다.
   다르면 훅이 저장을 막는다. 구간 이름이 marks 로 읽혔는지도 본다.

9. **음표 받아 적기** — [transcribe.md](transcribe.md) 를 읽고 따른다: set_timing → measure_images →
   write_measures (전부) → ⚠ 마디 다시 보기 → refine_timing 으로 1마디 1박 검산. 사용자가 송 맵에서 음표를 고치는 출발점이다.

10. **save_result(anchor, bpm, beats)** — 송 맵은 새 버전("AI 악보")으로 저장되고 활성화된다
   (사용자의 기존 버전은 남는다). names 를 생략하면 띠의 구간 표시를 쓴다.

11. **report(status, summary)** — 한국어로: 마디 수, 템포, 1마디 1박, 구간 수, 고친 것, **확신 없는 것**
    (예: "37~40마디 띠가 시간상 5마디라 반복으로 봤음", "첫 마디를 2박으로 봤음"). 실패면 왜인지.

## 주의

- 띠 마디 수의 합 = 악보 마디 수 = 송 맵 마디 수 의 기준이다. 곡 길이보다 송 맵이 길게 이어지는 것은
  괜찮다 (뒤는 비어 있는 마디가 된다).
- 영상 속 연주자는 **원곡 반주에 맞춰** 친다. 그래서 소리 맞대기(offset)가 정확하다. 단, 영상 앞에
  인사·카운트가 있으면 offset 이 크게 나올 수 있다 — 정상이다.
- 진행 커서·Next 미리보기·가사는 띠 뽑기가 알아서 지운다(움직이는 색은 무시하고, 대표 그림은 중앙값).
  그래도 띠에 남아 있으면 상자(box)를 더 좁게 잡는다.
- 한 번에 다 맞추려 하지 말고, 표(strip_table)와 그림(show_strips)으로 확인하며 고친다.
